2. File di Configurazione (config)
All'avvio della web app, il sistema deve rilevare un file di configurazione (config) contenente i seguenti parametri impostabili:
Modifica del tempo di inattività della web app.
Modifica del tempo di attività del terminale SSH.
Modifica del numero totale di persone con accesso contemporaneo alla web app (valore base: 10 utenti contemporanei).
Modifica del numero totale di persone che possono accedere contemporaneamente ai terminali di ciascun singolo robot (es. max 2 terminali aperti per singolo robot, valore base: 1).
Modifica delle impostazioni per il caricamento file di massa.
Limite massimo per il caricamento file sia su server che su robot (preimpostato a 3 GB).
Parametri di configurazione aggiuntivi per esigenze future (es. numero massimo di robot nella flotta, numero massimo di accessi contemporanei con lo stesso account, ecc. - da confermare con Daniele).

3. Gestione File e Navigazione Cartelle
Caricamento file di massa su server e robot: possibilità di selezionare uno o più file e specificare i robot di destinazione e/o server (senza limite massimo prefissato, parametro modificabile in config).
Permessi di navigazione e gestione cartelle:
Admin: navigazione completa con permessi di inserimento ed eliminazione file ovunque.
Operatore: navigazione limitata alle sole cartelle autorizzate.

Specifiche e Requisiti di Sistema
1. Gestione Robot e Impianti
Durante la fase di creazione di un nuovo robot, il campo relativo al cliente è obbligatorio, mentre l'inserimento del nome impianto è opzionale.
2. Selezione del Percorso di Trasferimento File
Quando si seleziona il pulsante di dimensioni ridotte «Invia al robot» o il pulsante «Invia al server», il sistema deve mostrare una finestra pop-up per la «Gestione File». All'interno di questa finestra, l'operatore deve poter inserire il percorso (path) desiderato sia selezionandolo direttamente sia digitandolo manualmente.

3. Validazione del File di Configurazione e Permessi di Navigazione
È necessario verificare il corretto funzionamento del file di configurazione (config) rispetto alle sue finalità. Bisogna inoltre integrare la possibilità di definire e limitare i percorsi (path) su cui ciascun operatore è autorizzato ad agire.
4. Gestione Avvisi di Inattività e Sessione
Modificare o implementare la finestra pop-up di avviso per inattività, sia a livello di terminale sia a livello generale di sessione. La finestra di dialogo deve contenere due opzioni:
Conferma (CONFIRM): Il timer di inattività viene azzerato, ripartendo dal valore predefinito (es. 15 o 30 minuti), e la finestra pop-up si chiude.
Esci (DELETE): Viene effettuato immediatamente il logout dalla sessione corrente.
Nota sulle operazioni in corso: Se un trasferimento di file è in esecuzione, la sessione non deve terminare per inattività.
5. Conferma Eliminazione File e Cartelle
Quando l'utente intende eliminare elementi dal file system, il sistema deve richiedere una conferma tramite pop-up. Se l'oggetto selezionato è una cartella, il messaggio di avviso deve specificare il numero totale dei file contenuti al suo interno che verranno eliminati definitivamente insieme ad essa.
6. Concorrenza e Controllo delle Sessioni
È consentito un massimo di un utente attivo per ogni sessione. Nel caso in cui si tenti un accesso simultaneo, il sistema deve notificare all'utente che la sessione risulta già avviata.
7. Limitazioni Interfaccia per Profilo Operatore
Per gli utenti con ruolo Operatore, è necessario rimuovere completamente il pulsante d'accesso al terminale (sia lato robot sia lato server), in quanto non dispongono dei permessi per utilizzarlo.
8. Struttura dei File di Log (Area Amministratore)
Gli utenti Amministratori disporranno di una sezione dedicata («Logs») per consultare lo storico degli eventi di sistema con file che saranno situati sul server:
Log di Accesso: Traccia gli eventi di login e logout, registrando l'utente, il livello di privilegio, la data e l'ora esatta dell'operazione.
Log Trasferimenti File: Traccia ciascuna operazione riportando nome file, nome utente, data, ora ed esito (successo/fallimento).
Nel caso di caricamenti massivi, la struttura di registrazione deve delimitare chiaramente il blocco delle operazioni tramite tag di avviso (es. INIZIO CARICAMENTO MASSIVO ... CARICAMENTO MASSIVO TERMINATO) elencando ogni file con i relativi dettagli di trasferimento.
9. Comportamento e Annullamento dei Trasferimenti Massivi
In caso di interruzione o annullamento manuale di un trasferimento massivo in corso:
I file il cui trasferimento è già stato completato non vengono rimossi e rimangono sul server/robot.
I file in corso di scaricamento non completati devono essere interrotti ed eliminati definitivamente, a meno che il trasferimento non sia ormai prossimo alla conclusione (in tal caso l'operazione viene portata a termine).
L'azione di annullamento agisce sull'intero blocco di trasferimento massivo e non sui singoli file singolarmente.
